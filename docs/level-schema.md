# 新增課程 / 關卡 / 食物 / 玩具 — 檢查清單

> 本檔**不是**用來限制玩法或規定題型,是把之前真的踩過的雷、跟結構上還沒踩但看得到的雷,寫成一份「加新東西前照著勾一遍」的清單。
> 相關程式:`app/config.js`(關卡資料)、`app/gen.js`(動態出題)、`app/bank.js` + `questions/*.xml`(可編輯題庫)、`app/quiz.js`/`app/english.js`(關卡引擎)、`app/store.js`(過關記錄/解鎖)、`app/art.js`(食物美術)、`app/toys.js`(玩具美術)、`app/screens.js`/`app/dex.js`(食物玩具名稱與圖鑑)。

---

## 為什麼需要這份清單

`3feb84e`(題庫大擴充)是真實發生過的事故:早期 XML 題庫只有十幾題、英文單字池 CVC 只有 31 個、magic-e 只有 12 個,小朋友玩沒幾輪就開始一直重複同一題。當時的修法是把池子擴大(XML 擴到 50+ 題、CVC→85、magic-e→68)+ 在 `quiz.js` 加回合內去重(`seenSigs`)。

從這個真實案例往外推,程式碼裡還有幾個**同一類、結構上已經埋著、還沒真的爆的雷**,一併列進來。

---

## 一、新增數學關卡(`config.js` 的 `math` 陣列)

每筆關卡二選一出題方式:

- **`gen: 'xxx'`**:動態程序出題,函式要註冊在 `app/gen.js` 的 `G.gen` 表裡。
- **`bank: 'xxx'`**:可編輯 XML 題庫,對應 `questions/<bank>.xml`,家長/老師改 XML 就能換題目,不用動程式。

### 檢查清單
- [ ] **池子夠大**:這關可能出現的「不同題目數」要 ≥ 回合題數(`CFG.questionsPerLevel` = 10)的 **5 倍以上**(≥ 50 題/種變化)。這是 `3feb84e` 事故後訂下的實際下限,`unit6~9.xml` 目前都在 50 題以上,新的 `bank` 也要比照。
- [ ] **`dedupKey` 抓對欄位**:`gen.js` 開頭已有規範註解——`display` 裡如果有「純裝飾、不影響題目本質」的欄位(例如水果圖案),不能讓它混進去重簽名,要另外回傳 `dedupKey` 只放數字/答案/目標等本質欄位。抓錯有兩種壞法:漏放本質欄位 → 池子被誤判變小、太快出現重複；誤放裝飾欄位 → 明明數字一樣卻被當成不同題,小孩會覺得「怎麼一直考一樣的東西」。`gen.js` 的 `shapeCompose`(用 `optsSig` 把選項排列組合也算進簽名,擴大有效池)是踩雷後修好的正確示範,可以當範本。
- [ ] **去重迴圈的上限不會幫你擋錯**:`quiz.js` 的去重迴圈重試到一定次數後會**默默放行重複**,不報錯不提示。池子不夠大時開發者不會收到任何警告,只能靠自己先算過池子大小。
- [ ] **`id` 是新的、獨一無二、以後不會被回收**:過關記錄跟解鎖狀態都是用 `id` 字串查 `d.levels[id]`,不是陣列位置。撞名 = 新關卡會接收到別的關卡留下的過關記錄(小朋友一進新關卡發現進度條已經滿了);改名或回收舊 `id` 給不同內容 = 同樣的資料錯亂。
- [ ] **加在陣列尾端,不要插進中間**:解鎖規則是「陣列位置上,前一關有沒有過關」,純看位置不看難度(`store.js` 的 `levelState`)。插進中間會讓它後面所有關卡的解鎖條件自動變成「這關新關卡要先過」——對已經玩到後面、原本已解鎖但還沒破到上限的小孩來說,原本能玩的關卡會突然變回鎖定。真的要插隊,先想清楚這個副作用。

## 二、新增英文關卡(`config.js` 的 `english` 陣列)

### 檢查清單
- [ ] **`play` 類型要是引擎認得的字串**:目前實際支援 `pick`/`match`/`trace`/`write`/`wpick`/`spell`/`wword` 七種(`config.js` 行內註解只列了前四種,是文件跟實作漂移的已知落差,新增玩法時記得回頭補註解)。打錯字沒有任何載入期檢查,是小朋友點進那關才在畫面上出錯。
- [ ] **單字池夠大**:`wordPool: 'cvc'` / `'magic_e'` 對應 `WORDS_CVC`(85 個)/`WORDS_MAGIC_E`(68 個),新關卡的 `count` 通常是 5~10,池子要維持在 count 的 **8 倍以上**,不要因為新增一個小池子的專屬字彙表就退回 `3feb84e` 之前的狀態。
- [ ] **`id` 命名與插入位置規則同數學關卡**(見上一節,同一套解鎖機制)。

## 三、新增食物(數學過關獎勵)

食物比玩具多一個**沒有自動化、需要手動同步**的地方,是目前最容易漏補的一步。

### 步驟
1. **`app/art.js` 的 `FOODS` 物件**加一個新 key 的繪製函式,原點為中心繪製,由 `drawFood()` 統一 `translate`/`scale`。
2. (選用)想讓豪華版有專屬構圖而不是自動縮小疊圖,在 `FOODS_DELUXE` 加對應版本;不加的話 `drawFoodDeluxe()` 會自動 fallback 用 `FOODS[key]`。
3. **`app/config.js`** 在某個數學關卡的 `bite`(單口食物)或 `feast.items`(大餐清單)填這個 key。
4. **`app/screens.js` 的 `FOOD_NAMES` / `FOOD_BASIC_NAMES` / `FOOD_DELUXE_NAMES`** 手動加中文名——**這是食物專屬、玩具沒有的一步**(玩具名稱是從 `config.js` 動態推導,食物是三份手寫表)。忘記加不會報錯,後果比顯示錯字更隱蔽:`screens.js` 的珍藏清單邏輯是 `if (!FOOD_NAMES[k]) return;`,**沒登記的食物會整格從珍藏館消失**,不是顯示預設字樣。

### 不能重複的規則
- **key 不能撞名**:`FOODS`/`FOODS_DELUXE` 是 JS 物件字面量,同一個 key 寫兩次**不會報錯**,後面那個會**悄悄覆蓋**前面那個的畫法。想抄一個既有食物當模板改造型時,複製貼上**務必連 key 名稱一起改**,不然會變成「全部關卡的蘋果突然被畫成新食物的樣子」這種詭異回歸,而且不會有任何錯誤訊息提示你。
- **語意不要重複**:加關卡前,先看一眼 `FOODS` 現有 key 清單(目前有 `apple/strawberry/orange/banana/eggcake/boba/sushi/pizza/bao/burger/fries/scoop/sundae/cake` 等)。如果想加的東西其實已經有對應美術,直接複用 key,不要為了同一種食物造第二個 key——這個目前沒有程式能自動擋,只能人工檢查。
- 圖鑑收藏清單(`dex.js` 的 `buildFoodCatalog`)跟珍藏館清單是動態掃 `config.js` 產生的,**不需要**額外去別的地方登記收藏名單,只要前面 4 步做完就會自動出現。

## 四、新增玩具(英文過關獎勵)

玩具是全物種共用一套(v9 之後),流程比食物單純,只有 2 處:

### 步驟
1. **`app/toys.js` 的 `TOYS` 物件**加一個新 key 的繪製函式,原點為中心、約 ±42px,由 `drawToy()` 統一縮放。
2. **`app/config.js`** 某個英文關卡填 `toyU`(中文名)+ `toyArtU`(key,對應 `TOYS` 裡的函式名)。

`screens.js` 的 `TOY_NAMES` 跟 `dex.js` 的 `buildToyCatalog` 都是**動態從 `config.js` 掃出來的**,不像食物需要手動補第三份表——這是 v9 統一玩具美術時已經做對的地方,新增玩具不用擔心圖鑑或名稱漏同步。

### 不能重複的規則
- 跟食物一樣:**`TOYS` 的 key 不能跟既有玩具撞名**,撞了會悄悄覆蓋既有玩具的畫法,不會報錯。
- 新玩具前先看一眼 `TOYS` 現有 key 清單,避免同一款玩具造出兩個不同 key。
