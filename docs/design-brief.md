# 設計外包規格（Claude Design Prompt System）

> 這份文件的用途：把「請設計師畫東西」變成一件**可重複、格式固定、拿回來就能落地**的事。
>
> 每次要新的寵物 / 房間場景 / 獎品 / 畫面，都從這裡組裝 prompt，不要重新發明說法。

---

## 怎麼使用這份文件

丟給 Claude Design 的 prompt 一律由四塊組成，順序固定：

```
[區塊 A] 專案前言        ← 每次必貼，不改
[區塊 B] 硬性技術限制    ← 每次必貼，不改
[區塊 C] 資產模板        ← 依這次要什麼，挑一個貼
[區塊 D] 回傳格式        ← 每次必貼，不改
```

拿回結果後，用文末的**驗收清單**檢查，通過才進入實作。

### 已組裝好、可直接複製的 prompt

| 檔案 | 用途 |
|---|---|
| `docs/prompt-pet-husky.md` | 哈士奇 3 個精緻度方案（Track A 起手） |
| `docs/prompt-ui-style.md` | 3 個 UI 風格方向 × quiz/room 兩畫面（Track B 起手） |

整份複製貼進 Claude Design 即可，不用自己組裝。之後要新資產時，照上面四塊自己組一份，
並存成同樣命名慣例的檔案（`docs/prompt-<主題>.md`），下次就不用重寫。

> 註：`docs/design-interactive-pet.md` 是**功能面**的改版計畫（電子雞化玩法），
> 跟這份**視覺外包規格**是兩件事，不要混用。

## 操作步驟（每次外包都照這個跑）

### 誰看什麼（重要）

| 文件 | 給誰看 | 說明 |
|---|---|---|
| **這份 `design-brief.md`** | 給人看 | 這是「怎麼組 prompt」的說明書，**不要貼給 Claude Design** |
| **`docs/prompt-*.md`** | 給 Claude Design 看 | 這是照 brief 組好的成品，**整份貼上去** |

貼 brief 本身只會稀釋指令 —— 裡面有一堆這次用不到的模板（問哈士奇卻附上食物/玩具模板）
和內部備註（驗收清單、程式端對應位置、色彩現況），會讓設計端抓不到重點。

### 準備（做一次）

```
make start
```
開 `http://localhost:4173`，把要改的畫面各截一張圖。
prompt 裡的「現況參考」只有文字，有截圖對照，設計端才知道要「從哪裡走開」。

### 探索階段

1. 到 claude.ai/design，進 `Children Learning Pets` project
2. **開新對話**（每個資產類型一個獨立對話，避免互相污染）
3. **Design system 選「無」** —— 見下方警告
4. 整份貼上對應的 `docs/prompt-*.md`
5. 附上截圖
6. 拿回方案 → 挑一個 → 回報給 Claude Code 落地

> ⚠️ **探索階段絕對不要掛 `Pet Academy Design System`。**
> 掛 design system 等於要求一致性，而探索階段要的是**差異性**。
> 一旦被既有 token 綁住，要來的 3 個方案會全部長成同一個樣子，這個階段就白做了。

### 標準化階段（方向選定後才做）

7. 把選中方向的「風格規則」寫成約束集，更新 `Pet Academy Design System`
8. **之後所有新資產才掛著它跑**，這時候一致性才是我們要的東西
9. Claude Code 同步建立 `app/theme.js` token 層

### 新增資產類型時

照區塊 A + B + C（挑模板）+ D 自己組一份，存成 `docs/prompt-<主題>.md`，下次就不用重寫。

## 區塊 A — 專案前言（每次必貼）

```
這是一個給小學低年級孩子的數學／英文學習 App，叫「寵物小學堂」。
孩子答對題目可以獲得食物和玩具，餵養自己的寵物、把牠養大，最後畢業收藏。

目標裝置：iPad Pro 11 吋，橫向，全螢幕。
使用者：6–9 歲兒童，用手指觸控操作。
氣氛：溫暖、鼓勵、不緊張。答錯不會有懲罰感的紅色警示。

重要：整個 App 的畫面不是網頁，是單一個 HTML canvas，
所有像素都由 JavaScript 的 2D 繪圖指令即時畫出來。
你的設計最後會被人工翻譯成繪圖指令，所以請嚴格遵守下面的技術限制。
```

## 區塊 B — 硬性技術限制（每次必貼）

```
## 可以使用
- SVG path（會用 Path2D 直接畫進 canvas，已驗證可行）
- 實色填充、線性漸層、徑向漸層
- 圓角矩形、橢圓、多邊形、貝茲曲線
- 線條描邊（可指定線寬、圓頭/方頭端點）
- 投影（單一顏色 + 模糊半徑 + 位移，不支援 spread）
- 整體透明度

## 不可以使用
- 點陣圖、照片、材質貼圖
- CSS filter、backdrop-blur、mix-blend-mode
- SVG filter（feGaussianBlur 等一律不支援）
- 任何外部資源（字體 CDN、圖片 URL、icon library 的 runtime 引用）
- 新的字體。字體鎖定為 "Andika", "Huninn", "Baloo 2", sans-serif
  （Andika 是識字教學字體，單層 a/g；中文 fallback 到 Huninn）

## 座標與尺寸
邏輯畫布固定 1194 × 834（= iPad Pro 11" 橫向的邏輯解析度）。
1 個畫布單位 = 1 pt，所以你標的座標可以 1:1 抄進程式，請標精確數字。
畫布外緣填色 #E8D9C8。

## 觸控
使用者是 6–9 歲兒童用手指操作。
可點擊元素高度不得小於 66，現有慣例是 84 / 96 / 100。
```

## 區塊 C — 資產模板（挑一個貼）

### C1 — 寵物物種

> ⚠️ **新增物種時,C1 必須跟下面的 C2(房間場景背景)一起委託,不可只交寵物角色。**
> 房間場景背景現在是新物種的必做項,不是選用加分——沒有專屬場景的物種會 fallback 通用壁紙房間,
> 之後同一批新物種**不允許**用這個 fallback。組 prompt 時把 C1 + C2 兩塊一起貼給設計端。

```
## 任務：設計一個「__物種名稱__」的寵物角色

這隻動物是一個獨立的「演員」：牠不跟任何其他物種共用造型結構 —— 沒有共用的臉、
沒有共用的身體、沒有共用的呼吸動畫。**請優先讓牠「像那種動物」**，
需要多精確的比例都可以做（長吻、分明的四肢、桶狀胸腔、細腿三爪…都歡迎）。

### 座標系
原點 = 腳底中心（站立的地面），y 軸向上為負。
這隻動物該多大由你決定，請回報牠自己的 bounds：
- `top`        最高點（含耳朵／角／冠毛，負值）
- `bottom`     影子／腳掌最低點
- `halfWidth`  最寬處的一半（含尾巴）

參考量級：中型四足動物約 `top -180 / halfWidth 96`；小型鳥類約 `top -96 / halfWidth 52`。
**沒有統一的外框，不要為了跟別的物種對齊而委屈比例。**

### 動作表（這份設計的主體）
程式只會對牠下這 10 個**語意指令**，怎麼演完全是這隻動物自己的事。
請逐項說明**這一種動物**會怎麼表現，並標出會動的部位、幅度、頻率：

| 指令 | 什麼時候用 | 你要決定的事 |
|---|---|---|
| `idle` | 沒事做 | 呼吸／重心／尾巴的靜態節奏 |
| `walk` | 在房間裡移動 | 步態（四足小跑？兩腳碎步？彈跳？滑翔？）、身體怎麼帶出方向感 |
| `eat` | 餵食 | 低頭啃？叼起來甩？啄？用前肢捧著吃？ |
| `play` | 陪玩 | 撲、拍、追、叼、頂 |
| `happy` | 過關慶祝 | 跳？搖尾？拍翅？轉圈？ |
| `sad` | 失落 | 耳朵／尾巴／頭怎麼垮下來 |
| `sleep` | 自發行為 | 趴著？縮成一團？站著睡？ |
| `rest` | 自發行為 | 半瞇眼的放鬆姿態 |
| `stretch` | 自發行為 | 這種動物真實的伸展方式 |
| `greet` | 打招呼 | 揮前肢？蹭？叫？ |

**方向感沒有標準答案。** 舊版規定每隻都要交「正面／3-4 側面／背面」三套，
結果每隻都被畫成正面娃娃。現在你可以自己選：
- (a) 五官與四肢往行進方向做**視差偏移**（不必另畫側面；哈士奇用這個）
- (b) 真的畫一套側面
- (c) 這種動物本來就正面呆呆的，走路只有腳在動（小雞用這個）

選哪個都行，講清楚即可。

### 節奏參數（跟造型一起交）
| 參數 | 意思 | 參考值 |
|---|---|---|
| `speed` | 走路速度（單位/秒） | 中型犬 62、小雞 74 |
| `legFreq` | 邁步頻率 | 四足 5.5、碎步鳥類 9 |
| `tailFreq` | 尾巴／翅膀擺動頻率 | 1 ~ 2.4 |
| `lean` | 走路時身體前傾量 | 四足 0.15、直立鳥類 0（改用左右滾） |
| `gait` | 步態名稱 | `trot` / `waddle` / `hop` / `glide` |
| `ambient` | 沒人理牠時自己會做什麼 | 動作 + 權重 + 間隔秒數 |
| `holds` | 每個動作演多久回到 idle | 1.6 ~ 4.6 秒 |

### 三個成長階段
幼幼 / 小寶 / 大寶。**不是整隻等比縮放**，請給各部位的比例差異
（幼犬是頭大、腿短、耳朵還沒立起來；成犬是身長、腿長、耳朵尖立）。
幼幼可以有專屬特徵（呆毛、還沒脫掉的蛋殼、胎毛）。

### 大寶配件 5 款
帽子、髮飾、圍巾這類戴在頭部或頸部的裝飾。
請標出掛載座標（相對頭部中心），配件是獨立繪製、疊在角色上的。

### 這些限制已經拿掉了（舊版有，現在沒有）
- ~~角色總高不得超過 366~~ → 自己報 bounds
- ~~一定要有 front / side / back 三個視角~~ → 方向感自己選表現方式
- ~~成長只能整體 ×0.85 / ×1.12~~ → 各階段比例自己定
- ~~造型必須是「一團可以被壓扁拉長」的結構，不要有依賴精確比例才成立的細節~~
  → **這條是舊版最大的問題。** 它等於要求設計端放棄一切讓動物像那種動物的細節，
  結果哈士奇只能是一隻灰藍色的圓身娃娃。現在角色不再被套用全域的擠壓拉伸，
  所有形變都由你在動作表裡自己定義，所以**請盡量做出物種特徵**。

### 現有 10 個物種（新增物種時避免撞型）
兔兔 rabbit｜倉倉 hamster｜斑斑 tabby（虎斑貓）｜蒙蒙 meerkat（狐獴）｜
豚豚 capybara（水豚）｜哈哈 husky（哈士奇）｜象象 elephant｜橘橘 xmascat（聖誕橘貓）｜
小雞 chick｜貓頭鷹 owl
```

### C2 — 房間場景背景

> ⚠️ **新增物種時必做,跟 C1(寵物角色)一起委託**——見 C1 開頭的提醒。

```
## 任務：設計「__物種名稱__」的房間場景背景

### 座標系
繪製在 440 × 340 的座標空間裡（程式會等比縮放去填滿實際房間框）。

### 版面切分（硬性）
- y = 0 ~ 160（上方 47%）：背景／牆面／天空。這一段可以放遠景。
- y = 160 ~ 340（下方 53%）：地面。寵物會在這裡走動。
- y = 160 附近是「牆與地的分界線」，必須看得出來，寵物的深度感靠它。

### 硬性規則
- **絕對不可以有前景遮擋物**。寵物會在地面區域自由走動，任何畫在牠前面的
  東西都會穿幫。所有物件都必須在寵物身後。
- 地面區域中央偏上會被程式蓋上兩塊地墊（食物區／遊戲區，各約 280×78 的橢圓），
  請不要在那個位置放重要細節。
- 場景要能承受不同亮度的寵物疊上去，避免大面積的高彩度色塊搶掉主角。

### 風格參考（現有的 4 個場景，新場景要跟它們是同一個世界）
- 象象：向日葵花園，青綠漸層底、葉片散佈、向日葵與雛菊
- 橘橘：聖誕紅底、冬青枝、金色四角星
- 小雞：稻草農場，米黃底、木柵欄、彩旗、程序化散佈的稻草
- 貓頭鷹：黃昏森林，四段漸層天空、徑向月暈、視差山丘、松樹、螢火蟲

### 這個物種的既有主題色（場景要與它協調）
wall: ____  dot: ____  accent: ____  deep: ____
```

## 請用這個格式交付

除了視覺稿之外，請附上可直接轉成程式的資料：

### 1. 繪製清單（依繪製順序，由後往前）
每一項給我：
- d          SVG path 的 d 字串（座標就用上面指定的座標系，不要另外正規化）
- fill       填色 hex 或漸層定義
- stroke     描邊色（沒有就省略）
- lineWidth  線寬（沒有描邊就省略）
- opacity    透明度（1 就省略）

漸層請寫成：
- 線性：起點 (x,y)、終點 (x,y)、色停站列表
- 徑向：圓心 (x,y)、起始半徑、結束半徑、色停站列表

### 2. 色票
這份設計用到的所有顏色，列成一張表，每個顏色給一個語意化的名字
（例如 wall-base / fur-shadow / accent-warm），不要只給 hex。

### 3. 風格規則
這份設計的內在規則是什麼？請明確寫出數字：
- 線寬有哪幾種？
- 圓角半徑有哪幾階？
- 有沒有統一的描邊？
- 陰影的參數是什麼？
這一段最重要 —— 之後所有新資產都要遵守同一套規則，所以規則必須是可執行的
數字，不能是「溫暖」「圓潤」這種形容詞。

### 4. 取材來源（如果有）
若參考了免費授權素材庫，請標明來源與授權條件。

## 驗收清單（我用的，不貼給設計端）

拿回設計後逐項確認，有任何一項不過就退回重做，不要硬吞：

- [ ] 每個形狀都能表達成 `Path2D` 吃得下的 `d` 字串
- [ ] 沒有用到 filter / blur / blend mode / 點陣材質
- [ ] 沒有引入新字體
- [ ] 座標用的是指定座標系，不是 0–1 正規化或任意畫布尺寸
- [ ] 顏色是明確的 hex 或 rgba，不是「淺藍色」
- [ ] 寵物：10 個語意動作逐項都有講怎麼演、bounds 三個數字齊全、
      三階段是「各部位比例差異」而不是等比縮放、節奏參數齊全、5 款配件含掛載座標
- [ ] 寵物：這隻的造型結構是自己的，沒有「跟現有某某物種一樣的臉/身體」這種交代
