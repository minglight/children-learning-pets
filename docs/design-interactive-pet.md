# 互動寵物改版計畫(電子雞化)

> 目標:女兒覺得「沒有很好玩」→ 把「解題拿獎勵動畫」改成「養成式電子雞」。
> 食物/玩具是**會被消耗的資源**,寵物**會成長、有心情**,小朋友解題的動機從「過關」變成「照顧我的寵物」。
> 狀態:Phase 1–3 皆已完成上線(schema v5)。
> **2026-07 家長回饋調整(schema v6)**:
> 1. 獎勵減量 — 數學過關 1 個食物(滿分/豪華 2 個,許願食物優先),配套 GROW 加重(餵 +4、玩 +6、每日首次 +2)。
> 2. 佈置(換擺設)移除 — 擺出的食物/玩具由 migration 轉進背包;不另做裝飾分類(成長配件+圖鑑已承擔收集/擁有感)。
> 3. 房間 2.5D — 寵物縮小、整片地板漫遊(近大遠小、轉身翻面),點地板可叫牠走過去。
> 未做:雙寵物互訪、金色食物庫存變體、限時挑戰(見 §3 殘項)。

---

## 1. 核心循環(為什麼會變好玩)

```
解題過關 ──獲得──▶ 食物/玩具(收進背包,會累積)
   ▲                        │
   │                        ▼ 回房間
寵物餓了/想玩了 ◀──動機── 餵食、陪玩(互動動畫,資源被消耗)
   │                        │
   └──「想看牠長大」◀── 寵物獲得成長值,階段成長、外觀改變
```

關鍵改變:現在的大餐/玩具是「一次性動畫,看完就沒了」;改版後獎勵**留在背包**,
小朋友要**自己決定什麼時候餵、餵哪個**,寵物吃掉後有反應、會長大 → 產生擁有感與照顧感。

## 2. 系統設計

### 2.1 背包(庫存)— 食物與玩具會累積、用掉就沒有
- 資料:`pet.inv = { foods: {key: 數量}, toys: {key: 數量} }`(本寵物獨立)。
- 取得:
  - 數學過關(≥90%)→ 該關 `feast.items` 的食物**進背包**(豪華版 7 份、一般 5 份)。
    「吃大餐」畫面改成「豐收畫面」:食物彈出後**飛進食物籃**,標題「收穫滿滿!」。
  - 英文過關 → 該關玩具 ×1 進背包(豪華版算 2 個或特別標記,見 2.6)。
- 房間顯示:食物區/遊戲區旁各放一個「籃子/玩具箱」,上面有數量泡泡。

### 2.2 餵食互動(房間內)
1. 點食物籃 → 展開托盤,顯示背包裡的食物(圖示+數量)。
2. 點一個食物 → 食物放到食物墊上,寵物**自己走過去**(沿用 `petLife` 的走路),低頭吃:
   - 咀嚼動畫(已有 `chew` 模式)+ 食物**一口一口變小消失**(3 口)+ 碎屑粒子。
   - 吃完隨機小反應(見 2.5),數量 −1,飽足 +,成長值 +。
3. 沒食物時托盤顯示「去數學餐廳解題就能賺食物!」→ 點了直接跳關卡圖(引流回學習)。

### 2.3 玩玩具互動
- 點玩具箱 → 選玩具 → 玩具放到遊戲墊,寵物跳過去玩:
  - 玩具彈跳/搖晃 + 寵物 `happy` 跳 + 愛心粒子,約 4 秒。
  - 玩完玩具「收起來休息」= 數量 −1(電子雞式消耗),心情 +、成長值 +。
- 文案避免「壞掉」的挫折感:「玩具累了,回去休息囉~」。

### 2.4 成長系統(寵物會長大)
- 資料:`pet.growth = { xp: 0 }`,階段由 xp 推導(不另存,避免不一致):
  | 階段 | xp | 外觀 |
  |---|---|---|
  | 幼幼 | 0–29 | 體型 0.85×,頭上呆毛 |
  | 小寶 | 30–99 | 體型 1.0×(現在的樣子) |
  | 大寶 | 100+ | 體型 1.12×,配件(兔兔=蝴蝶結、倉倉=小領巾) |
- 成長值:餵食 +2(豪華食物 +4)、玩玩具 +3(豪華 +6)。
- 升階瞬間:房間內全螢幕慶祝(光圈+彩帶+寵物旋轉跳),「兔兔長大了!」,語音+音效。
- `pets.js` 的 `draw(petId, ctx, t, o)` 加 `o.stage`,由呼叫端從 store 取得;未傳=現狀(向下相容,quiz 等畫面不用全改)。

### 2.5 吃完的「小變化」(隨機驚喜,維持新鮮感)
每次吃完隨機一種:
- 滿足打嗝(音效+臉頰泛紅)/ 開心轉圈 / 原地蹦三下 / 愛心大爆發 / 講一句感謝的話(擴充 talk 池)。
- 倉倉限定:臉頰鼓成兩倍再慢慢消(已有頰囊動畫基礎)。
- 低機率(1/8):吃出「閃亮星星」→ 額外 +1 成長值,小朋友會期待。

### 2.6 心情與飽足(每日回訪動機,溫和不懲罰)
- 資料:`pet.care = { date, fed: 0, played: 0 }`(跨日重置計數,不做「餓死」)。
- 顯示:房間寵物頭上兩顆小圖示(飯碗、球),當日還沒餵/沒玩 → 圖示半透明+寵物偶爾冒泡泡「我肚子餓了~」「陪我玩好不好?」;餵過/玩過 → 圖示亮起,寵物笑咪咪。
- **不做**負面狀態(不生病、不離家出走)— 目標客群是小一,只給正向回饋。
- 每日首次餵食/陪玩額外 +1 成長值(鼓勵每天回來)。

### 2.7 互動動畫(直接摸寵物)
- 房間裡**點寵物**:摸頭 → 瞇眼+愛心;連點 3 下 → 搔癢大笑翻滾。
- 長按:寵物跟著手指方向看(眼睛/頭微轉)。
- 這些純娛樂、無資源消耗,讓房間「活起來」。

## 3. 讓「解題本身」更好玩的點子(優先序由上而下)

1. **寵物許願**(強推薦):寵物頭上冒願望泡泡「好想吃壽司…」→ 指定到「會掉壽司的那一關」;完成願望成長值×2+特別感謝動畫。把「今天要練哪關」變成寵物的請求,情感驅動最強。
2. **連對 Combo**:連續答對時進度點變火花、第 3 題起寵物戴上小墨鏡/舉牌「3 連對!」,答錯歸零。刺激又無懲罰。
3. **收集圖鑑**:食物圖鑑+玩具圖鑑(吃過/玩過就點亮),收集慾=長期動機;入口放房間掛畫。
4. **神秘金色食物**:過關時 1/10 機率獎勵變金色版(成長值×2),開獎的期待感。
5. **第 10 題儀式感**:最後一題答對 → 慢動作+全螢幕彩帶,收尾爽感。
6. **答錯友善提示**:同一題錯第 2 次,寵物給提示(「先算個位喔」),把挫折變陪伴。
7. **雙寵物互動**(後期):兔兔房間偶爾倉倉來作客,一起吃點心。

## 4. 題庫改進(Phase 1,subagent 實作中)

- **同一回合(10 題)絕不重複**:quiz.js 以題目簽名去重;XML 題庫以洗牌佇列+回合內用過即跳過。
- **每關題池 ≥50**:
  - `questions/unit6~9.xml`:各 30~32 題 → ≥50 題(格式不變,家長仍可自行編輯)。
  - `gen.js`:addWithin10/subWithin10 加入 0 的變化;mulIntro/mulBridge 擴大範圍;shapeFind 加「顏色+形狀」變化(紅色的圓形…,8 形×7 色);shapeCompose 以選項組合去重。
  - 英文:CVC 單字 31→≥50、magic-e 12→≥30;字母關卡天然上限 26 字母,回合內本來就不重複。
- 驗證:node 腳本斷言各生成器相異題目 ≥50、答案在選項中;XML 用 xmllint + 腳本驗「恰一個正解」。
